# v4.1 security review — local implementation

- **Admission:** API transport authentication and assertion signing are separate. A read-only live session query resolves the claims, and the verifier checks current policy, audience, issuer, expiry and one-time assertion ID. No configured fallback. Login semantics and per-event authorization remain. The daemon still shares the trusted service UID and is not an independently secured network identity provider.
- **Cancellation and quota:** async cleanup handles late reservations and response send failures. Lost releases or an unavailable authority remain bounded by the lease TTL. The daemon bounds concurrent request handlers and read time. Forward-skew request nonces are retained for their full validity window.
- **Worker:** application mutation requires a current lease. Agent status only reflects its originating claim. Trusted operator routes write audit events through a separate internal entrypoint. Python functions are not a sandbox, and the trusted worker process still has DB permissions. Independent least-privilege process isolation is not established.
- **Artifacts:** prior generations are retained, POSIX staging is synced, and a real child-process interruption test detects divergence between the manifest and the promoted directory. This is not actual power-loss or filesystem durability evidence. Retained generations need operator-managed retention.
- **Provider/host:** No paid API, authentic per-response reconciliation, provider-side hard-cap evidence, independent Linux rootless Docker, real TLS/CRL or production test was run. No unknown charges were cleared. Production admission stays **DENIED**.
