# v4.0 — Lease-fenced worker telemetry and crash-boundary artifact audit

`store.save_artifacts` is intentionally disabled and always raises: updating a manifest without a worker claim and synchronized filesystem publication is unsafe. Production code uses `publish_artifacts` with the per-claim lease and SQLite transaction. Worker-owned agent `event`, `phase`, `agent_start`, successful `agent_finish`, task plans, handoffs and manual-approval release now pass the same lease. Trusted administrative/test functions without lease remain internal only; do **not** expose them to untrusted requests or new workers.

`app.artifact_audit.audit()` / `scripts/audit-artifact-publication-v40.py` reports (read-only): surviving `.wfs-stage-*` and `.wfs-previous-*` directories, manifest with missing delivery, unmanifested output, file checksum mismatch, unowned project folder and unsafe symlinks. It does not repair or delete anything. The CLI requires an existing DB; it refuses to create/migrate one. Example: from project root, after stopping worker and taking a matched backup, `PYTHONPATH=. python scripts/audit-artifact-publication-v40.py --report /private/new-audit-file.json`. An exit status of 2 means manual investigation is required.

**Power-loss limitation:** SQLite commit and OS `rename` are not a crash-atomic transaction. A process can die between directory promotion and SQLite commit. An audit can detect symptoms, not reconstruct every physical disk state. Never auto-delete or promote backup/staging folders; compare original hashes and restore a matched backup under operator supervision. Existing `artifacts.verified` still refuses changed output contents.

Negative tests in `tests/test_v40_store_fencing.py` and `tests/test_v40_artifact_audit.py` include stale worker writes, concurrent takeover, cancellation, simulated crash after old-dir rename, modified outputs and unmanifested/symlink files. They are **local simulations**, not actual power-loss, filesystem fsync durability or independent runner host tests.
